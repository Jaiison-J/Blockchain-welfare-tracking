Key Blockchain Concepts

Core theoretical principles demonstrated by this application.

🌱

Genesis Block

The first block ever created in a blockchain (Block #0). It has no predecessor, so its previousHash is hardcoded to "0".

📦

Block

A structured data record containing an index, timestamp, transaction data (beneficiary, scheme, amount), previous block hash, and its own cryptographic SHA-256 hash.

📝

Transaction

The individual welfare payment record. Captures citizen details, scheme name, disbursed funds, department, and a unique tracking ID.

🔐

SHA-256 Hash

A deterministic, one-way 256-bit cryptographic hash function. Even the slightest alteration in the input data produces an entirely different 64-character hexadecimal digest (Avalanche Effect).

🔗

Previous Hash

The cryptographic glue that chains blocks together. Each block stores the exact SHA-256 hash of the block before it, forming an unbroken, tamper-evident chain.

🛡️

Blockchain Verification

The audit process that recomputes each block's hash and verifies that every previousHash pointer precisely matches the preceding block.

🚨

Tamper Detection

If an unauthorized actor alters an amount (e.g. ₹5,000 to ₹50,000), the recomputed hash diverges from the stored hash, immediately exposing fraud without central authority.

💾

Client Persistence

The ledger is stored locally in the browser via localStorage, allowing students and evaluators to refresh or close the tab without losing the state.

Project Information & Documentation

Summary for Project Overview & Documentation

Problem

Traditional Welfare Record Fragility

Traditional welfare distribution records maintained in centralized databases are prone to unauthorized modifications, data tampering, phantom beneficiaries, duplicate claims, and lack of auditable transparency between departments and the public.

Blockchain Solution

Cryptographic Transparency & Immutability

Each welfare disbursement is recorded as an immutable transaction inside a cryptographically linked block. The combination of SHA-256 hashing and previousHash linking makes any retrospective modification mathematically detectable.

System Flow

End-to-End Cryptographic Pipeline

Government Official → Welfare Transaction → Block Minting → SHA-256 Hash → Immutable Chain → Tamper Verification
Technology Stack: Pure HTML5, CSS3, JavaScript (ES6+), Web Crypto API (SHA-256), LocalStorage
